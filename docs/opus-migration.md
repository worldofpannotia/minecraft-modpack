# Moving the in-game guide from Patchouli to Opus

Written 2026-10-07 on branch `feat/opus-guide`. Everything described here is committed on that branch and **has not been
run in game yet**; only the Opus validator has been run on it (`0 errors, 0 warnings`).

## Short answer

Converting the Patchouli book mechanically would have been easy for the markup and pointless for the content:

* **The Patchouli book is the 13.x "HIGH TECH" book.** Patchouli is not in the 18.x manifest, and about 25 of the book's 54 entries
  document mods that are gone (Tech Reborn, AE2, Botania, Building Wands, Macaw's, Decorative Blocks, Rings of Ascension,
  Fabric Furnaces, Linked Storage...). Several others describe behaviour that no longer holds (for example "beacon beams
  hide under glass" is now a carpet, and "trades never lock" is off in the Villager Tweaks config).
* **`docs/guide/` is already Markdown, and already Opus-shaped** (tables, `> [!NOTE]` callouts, relative `.md` links). It
  needed a path-rewriting script, not a rewrite.

So the Opus book is built from two sources:

1. `docs/guide/**` is synced into the book by `node scripts/build-opus-guide.mjs` (39 pages). Re-run it after the docs
   pipeline changes `docs/guide/`.
2. A hand-written **Pack highlights** chapter (7 pages) carries over the friendly voice of the old book for the topics that
   are still true, and uses Opus widgets (`recipe`, `item`, `entity`) where the old book had spotlight and crafting pages.

Result: 6 chapters, 45 pages, 8 tags, validator clean.

## Where things are

| Path | What |
|---|---|
| `client/overrides/resourcepacks/pannotia-guide/` | Resource pack holding the book. Zipped by `build-client.mjs` like every other pack and loaded by Global Packs. |
| `.../assets/pannotia/opus-books/pannotia/` | `book.yml` plus `en_us/`. Book id is `pannotia:pannotia`. |
| `en_us/index.md`, `02-highlights/`, `book.yml` | Hand-written. Never touched by the script. |
| `en_us/01-getting-started.md`, `03-reference/`, `04-mods/`, `05-datapacks/`, `99-appendices/mod-list.md` | Generated by `scripts/build-opus-guide.mjs`. Do not edit by hand. |
| `client/overrides/datapacks/guide-book/` | Gives every player the book on first join and adds a craftable replacement (book + compass). |
| `client/overrides/patchouli_books/` | **Left alone.** Nothing in 18.x reads it any more; delete it when you are happy with the Opus book. |

Check it with `java -jar opus-fabric-26.2-1.0.1.jar client/overrides/resourcepacks/pannotia-guide`.

What the script does to the docs: maps each old path to its chapter, rewrites relative links to match, adds `icon:`
frontmatter, strips the `<!-- maintainer: ... -->` comments (Opus warns on raw HTML), and escapes stray `<angle>` text such as
`"<link>"` in command tables so it is not read as an HTML tag.

## What did not map cleanly

| Patchouli feature | Opus | What I did |
|---|---|---|
| `crafting` pages (33) | `recipe` widget, but **recipe ids are not resolved yet** (inline definition only) | Only recipes for mods still in the pack were rewritten inline (Gravestone, Monocle). The other 31 belonged to removed mods. |
| `image` pages (21, about 60 PNGs in `config.old/paxi/resourcepacks/...`) | No image support (`ideas/reader/images-and-textures.md`) | Dropped. The PNGs are untouched in `config.old/` if images land later. |
| `spotlight` pages (78) | `item` widget | Used where useful. Most spotlights were for removed mods. |
| `link` pages (24) | Markdown links | Opus can open `https://` links. Where a mod page is relevant the generated guide already has it. |
| `$(l:patchouli:...)` cross-links | `[text](path.md)` | Internal links are validated at load. |
| Entry icons with player-head NBT (9 entries) | `icon: item:ns:id` only | Used plain items (`zombie_head`, ...). Custom skull icons are not possible. |
| Macros `$(li)`, `$(br2)`, `$(thing)`... | Lists, paragraphs, `**bold**` | Hand-converted. |
| Book given by Patchouli | F7 only opens `opus:guide`, no first-join gift | `guide-book` datapack (see below). |

## Giving players the book

The Opus F7 key opens only the bundled `opus:guide`. A pack book needs the `opus:book` item with a book-id component.
Opus has no first-join gift, so `guide-book` does it:

* advancement `pannotia_guide:welcome` (tick trigger) runs `pannotia_guide:give_guide` once per player, which does
  `give @s opus:book[opus:book_id={book_id:"pannotia:pannotia"}]`
* recipe `pannotia_guide:guide_book`: book + compass, in case someone loses it

## Things to check in game

1. The book opens, the table of contents lists six chapters, and the widgets on the highlights pages render (the
   Gravestone and Monocle recipes use a `#minecraft:signs` tag and a modded result id).
2. The give command and the recipe result's `components` actually produce an `opus:book` that opens the right book.
3. `pack.mcmeta` for the resource pack: I used `min_format 84` / `max_format [100, 0]` as a guess for 26.2; confirm the real
   resource pack format and tighten it. (The datapack copies the existing `world-of-pannotia` format.)
4. Long pages: `03-items-index` is ~29 KB and `99-appendices/mod-list` ~41 KB. Check scrolling and search are comfortable.
5. Link tooltips, and the `\<link\>` escaping in the controls tables.
6. The first-join advancement also fires for existing worlds, so existing players get the book once.

## Findings for the Opus mod

Proposals only, nothing was changed in `~/code/minecraft-mods/opus`:

* **Javadoc on `BookIdComponent` suggests `opus:book_id="mymod:field_guide"`, but the codec is a record with a `book_id`
  field**, so the command is `opus:book_id={book_id:"mymod:field_guide"}`. Either the docs or the codec should change (a
  plain-string codec would make the shorter form work). The same wording is in the Opus Guide's "For pack authors" page.
* **A pack cannot make F7 open its own book.** A configurable default book (or a book list screen when more than one is
  installed) would help every pack.
* **No first-join or "give book" mechanism**, which is what `guide-book` works around.
* **Recipe ids are accepted but unused**, so every recipe has to be spelled out inline. That is the biggest cost of a port
  from Patchouli (`ideas/authoring/server-recipe-lookup.md`).
* **Images**: the old book leaned on screenshots (21 image pages).
* **Raw HTML warns**, so HTML comments in Markdown are not usable as maintainer notes; the generator strips them.
* Data point for `ideas/authoring/patchouli-migration-tool.md`: a converter would mostly be the macro translation plus
  recipe lookup from mod jars; content was the expensive part, not markup.
